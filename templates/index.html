flagship — Colophon

A CMS where “published” is a receipt, not a spinner. In a book, the colophon is the note at the back saying how, when and by whom it was printed. This does that for a website: every publish is a numbered release, and a probe reads the release marker off the live page before the product calls it done.

PostgreSQL is the only authority — RLS decides who sees what — outbox commits intent before any external call — release generations only move forward.

How the work is judged

Proof over breadth.
A feature counts when its failure behaviour is tested and the evidence is stored — never when the screen exists. Every feature ships with the trio: regression tests in CI, a separate testbed app driving the real HTTP API, and a load scenario with committed results.
Truthful states.
“Accepted” presented as “done” is the industry’s favorite bug. Here an accepted publish is pending until a probe sees it live, and an unmeasurable check stays uncertain rather than borrow confidence.
Kill it at any moment.
Crash tests have catalogue numbers (F01–F09 and counting). Bugs get a replayable seed: colophon-sim --seed N --trace. Killing things on purpose is the demo, not the edge case.
Bounded everything.
Every queue, body, page, cache, retry loop and pool has a limit and a deadline — a bound you can’t name is an outage you haven’t met yet.
No AI hype.
Agents and scripts work through the same API and the same permissions as everyone else — draft-only, on budgets reserved in Postgres, never allowed to approve their own submissions. Safe automation is a tested milestone, not a paragraph.

Asked plainly

Why build in the open, including the mistakes?

Because “proof over breadth” can’t be claimed, only shown. A build log that includes the failures is the difference between saying a system is reliable and letting you check.

Is any of this usable yet?

Honestly labelled: Colophon is pre-0.1 — it runs on my laptop and CI, and its own site says so. The service monitor has an installed release. The runtime is mid-build. Nothing here is marketed ahead of its evidence.

Why Rust?

Because “bounded everything” is easier to keep than to promise: one type system for the error envelope, explicit deadlines on every I/O await, compilers that refuse what production would regret, and simulators that replay failures deterministically.

How minimal is this site, really?

Zola generates it; the output is one documented stylesheet (width, font, spacing — all of it), one small script for the theme toggle, no tracking, no webfonts. Layout is tables, accordions are <details>, the ticker is a <marquee>. View source; it fits in your head.
